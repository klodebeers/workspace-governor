# Workspace Governor Learnings

**Status:** Non-authoritative living record.
**Retention rule:** `plans/reference/HUB-MANAGEMENT-predecessor.md` § Durable
learning retention, carried forward. Retain an entry only when completed work
reveals a non-obvious finding likely to prevent repeated investigation, repeated
failure, or an incorrect future classification. Do not record routine facts,
transient status, raw tool output, or semantic duplicates.
**Promotion rule:** if a learning creates or changes required behaviour, the
authoritative owner is updated and the learning becomes a pointer. An entry here
never defines behaviour.

## Learned in this backoffice

- `L-007` | Trigger: committing a `.ps1` for a Windows operator | Finding: Windows PowerShell 5.1 reads a non-BOM file using the system ANSI code page, and the third byte of a UTF-8 em dash decodes to a character PowerShell accepts as a **string delimiter** | Consequence: keep `.ps1` sources pure ASCII; the failure presents as a cascade of unrelated syntax errors | Owner: `STATE.md` stop conditions; `evidence/POWERSHELL-EXECUTION-2026-08-20.md`
- `L-008` | Trigger: naming a loop variable in PowerShell | Finding: variable names are case-insensitive, so `foreach ($r in ...)` and a result object `$R` are one variable | Consequence: a loop silently destroys the container; use descriptive loop names. Detected by `scripts/Assert-ScriptStructure.py` check S4 | Owner: `DECISIONS.md` D-18; `evidence/SCRIPT-STRUCTURE-DEFECTS-2026-08-20.md`
- `L-009` | Trigger: reasoning from any tool output | Finding: a display limit, a filter, or a field-shaped query silently produces a partial result that reads as complete. This occurred three times in one session -- a `^[+-][^+-]` grep filter that dropped every matching line, a transcript search scoped to one message shape that found nothing and was reported as absence, and a key listing truncated to twelve entries that hid the most duplicated block | Consequence: before concluding absence, re-run with the simplest unfiltered method available -- plain `grep` over raw bytes, or an unlimited listing. Absence from tool output is not absence in the system | Owner: `AGENTS.md` § Evidence standard; `rules/VERIFICATION-RESOLUTION.md`
- `L-010` | Trigger: choosing a verification method | Finding: an environment capability assumed absent may be obtainable in minutes; "no PowerShell here" was accepted untested and three hand-rolled static gates were built on that premise, none of which could detect a parse error because none was a parser | Consequence: test for the real tool before building a substitute for it | Owner: `rules/VERIFICATION-RESOLUTION.md`; `DECISIONS.md` D-20
- `L-011` | Trigger: sizing the canonical root bootstrap file | Finding: the instruction budget is shared across the whole root-to-cwd chain, consumed root-first, and truncates mid-content with no signal to the model | Consequence: an oversized root file silently starves every nested one. Normative outcome promoted -- see owner | Owner: `DECISIONS.md` D-29; `evidence/RUNTIME-CONVENTIONS-2026-08-20.md`
- `L-012` | Trigger: vendoring the canonical Hub into a consumer repository | Finding: project-root discovery stops at the first `.git` and never walks past it, so a nested checkout becomes its own project root | Consequence: the consumer's own root instruction file stops loading entirely, silently. Use a symlink or adapter projection, not a nested repository | Owner: `DECISIONS.md` D-29; `evidence/RUNTIME-CONVENTIONS-2026-08-20.md`
- `L-013` | Trigger: correcting an entry in an append-only record | Finding: a correct finding does not license a non-compliant mechanism -- the fix for a wrong entry in an append-only file is an appended superseding entry, never an in-place edit | Consequence: restore the original verbatim and append the correction; verify by confirming the diff against the pre-edit commit contains no deletions | Owner: `DECISIONS.md` D-32; `AGENTS.md` § File ownership
- `L-014` | Trigger: choosing a source to verify against | Finding: verification failed twice in this project for opposite reasons -- excessive depth on low-risk questions, then the wrong source on a high-consequence one. Depth and source are independent | Consequence: match depth to risk, but always check the authority that holds the answer. Per-class authorities, and what is explicitly not authoritative for each, are named in the rule; do not re-derive them | Owner: `rules/VERIFICATION-RESOLUTION.md` § Authority selection; `DECISIONS.md` D-34
- `L-015` | Trigger: emitting JSON evidence from Windows PowerShell | Finding: `Set-Content -Encoding UTF8` writes a **BOM** on PowerShell 5.1, and a standard JSON parser rejects it -- Python's `json.load` raises and needs `utf-8-sig` | Consequence: machine-readable evidence must be written with a no-BOM encoder, or every downstream consumer needs a workaround. Content correctness does not make evidence usable | Owner: `DECISIONS.md` D-36; `STATE.md` open work item 16
- `L-016` | Trigger: a reported defect, or verifying a move or deletion | Finding: a rename has two reference directions and a deletion has its own; checking only references *to* a moved file certified a class as clear while eleven instances stood. And the sweep's own check was wrong twice -- root-relative resolution made valid sibling references look dangling, and trailing-separator tokens were discarded so directory references were never examined | Consequence: sweep the class, not the instance; verify the check against a known instance and a known-good one before trusting it; record legitimate exceptions in the check so it does not train people to ignore it | Owner: `rules/VERIFICATION-RESOLUTION.md` § Defect class; `DECISIONS.md` D-39
- `L-017` | Trigger: needing live GitHub data for a repository that a session's allowlist names under an older name | Finding: the session repository scope is a snapshot taken at session start, so a rename leaves it holding the pre-rename name and calls under the new name are refused as out of scope. The API itself follows the rename redirect, so a call under the **old** name returns the renamed repository's current data | Consequence: after a rename, query under the name the session is scoped to and read the result as the current repository. Do not conclude a repository is unreachable from a scope refusal. Unauthenticated `git ls-remote` remains useless either way -- it fails on credentials, not on absence (`L-014`) | Owner: `rules/VERIFICATION-RESOLUTION.md` § Authority selection
- `L-018` | Trigger: writing a migrated artifact into a live authority | Finding: the reasoning that justifies a migration is not part of the artifact. Retirement arguments, rename maps, "why this file exists" sections, not-yet-migrated ledgers and a schema description arguing with its predecessor all read as authority once they sit in the live tree, and the directive keeps management and migration state out of it | Consequence: live artifacts carry a short provenance identifier and a superseded-source list; the argument lives in the backoffice evidence record. Write the evidence record first, then keep the artifact to what a consumer needs | Owner: `DECISIONS.md` D-52
- `L-019` | Trigger: claiming a null or absent reference is deliberate | Finding: `null` plus an explicit status is safe where a placeholder path is not. Writing eleven eventual paths would have created eleven dangling references in one commit, and the schema can enforce the pairing in both directions so the honest form is the only valid one | Consequence: express "does not exist yet" in the data model and let the validator hold it, rather than trusting future discipline | Owner: `DECISIONS.md` D-46
- `L-020` | Trigger: placing a new asset where an index already exists | Finding: being findable is not the same as having standing. The catalog declares itself non-authoritative and the root contract says load only routed owners, so an artifact declaring itself "the single entry point" was self-appointed -- discoverable and normatively weightless | Consequence: check both halves. Index the asset where discovery lives, and give it standing in the document that owns bootstrap, without touching the precedence table that governance owners use | Owner: `DECISIONS.md` D-49
- `L-021` | Trigger: stating a verification result in a durable record | Finding: "validated against 8 negative cases" was true when run and unreproducible from any repository the next day. A number in a record with no artifact behind it is agent confidence wearing the shape of evidence | Consequence: if a claim is worth recording durably, the check becomes a committed script and the record names it. Results belong in the backoffice record, not in a live index whose own header says presence proves nothing about verification | Owner: `DECISIONS.md` D-53; `scripts/Test-HubRegistrySchema.py`
- `L-022` | Trigger: transforming source content and describing what changed | Finding: four separate provenance claims were wrong in the same direction -- overstating novelty. A domain-selection step was called newly authored when the source stated it in prose in three files; an entry-point count said three where eight locations existed; a role sentence was rewritten without marking it; a source `must` was reclassified as "not an instruction" | Consequence: before claiming something is new, grep the whole source package for it, prose included -- the machine-readable declarations are not the whole source. Where content can be generated from the source instead of retyped, generate it: fidelity then holds by construction rather than by assertion | Owner: `DECISIONS.md` D-44
- `L-023` | Trigger: reusing a check on a repository it was not calibrated for | Finding: the reference sweep that reported 0 dangling on the canonical Hub reported 1022 on this backoffice, essentially all false -- bare filenames in prose, git refs, `owner/repo` names, paths inside other repositories. It also crashed on the first BOM-carrying JSON evidence file it opened | Consequence: a check enforces its own scope, because 1022 findings look like a result and an operator will not remember the calibration. Refuse to run outside the calibrated tree; read `utf-8-sig`; report an unparseable file as a failure, since an unreadable file is an uncovered file rather than a passing one | Owner: `scripts/Assert-ReferenceIntegrity.py`; `DECISIONS.md` D-36
- `L-024` | Trigger: consolidating the same material from several sources into one place | Finding: obligations travel with knowledge and get dropped when the knowledge moves. Merging four formula blocks into one context file silently lost three source musts and softened two more, because the destination was designed to state facts and the sources stated duties | Consequence: separate the two before merging. Facts go to the new owner; each obligation is either placed with an owner that exists or recorded as owed to a named future owner. Recording that an obligation was dropped is not a carrier for it | Owner: `DECISIONS.md` D-61
- `L-025` | Trigger: any review of your own work | Finding: reviewers given the author's rationale confirm the rationale. Four reviewers denied that rationale and given only source, approved scope and result found lost obligations, an unenforceable primary key, an unresolvable folded id, four untrue index claims, and two logic bugs plus four blind spots in the verification scripts themselves -- on a state two earlier reviews had already passed | Consequence: withhold the rationale, choose boundaries from the actual change rather than from the story of it, and require every finding to be verified against source before it is accepted or rejected. Record rejections with reasons so they are not relitigated | Owner: `DECISIONS.md` D-60
- `L-026` | Trigger: writing or reusing a check | Finding: five checker defects in one session, each of which made a clean result meaningless -- a skipped check reported as passed; fixtures chosen by the wrong property, producing a false failure on correct content; a counter incremented twice, printing double coverage; case-sensitive patterns reporting present content as absent; and a `$id` resolved as a path, which passed the defective relative form and skipped the correct absolute one | Consequence: prove a check in both directions before trusting it -- inject the defect it should catch, and confirm it passes clean content. A check that cannot run must fail, never skip. Treat any "0 findings" from an unproven check as no information | Owner: `scripts/Assert-HubSourceFidelity.py`; `DECISIONS.md` D-53
- `L-027` | Trigger: claiming content was generated or carried from a source | Finding: a commit claimed routes were "generated from the source files, so fidelity holds by construction" -- but the generator was an uncommitted inline script, so nothing could re-derive it. The claim was true and unverifiable, which is the same failure as an unverified claim | Consequence: prefer a committed verifier over a claim of construction. A verifier re-reads both sides on demand; a generator that has been thrown away proves nothing | Owner: `scripts/Assert-HubSourceFidelity.py`
- `L-028` | Trigger: sweeping a defect class you found | Finding: the formula-obligation sweep found three of four. The fourth was handled differently and silently, so a reader could not tell whether it was met, owed, or lost -- and the record showed three owed, which reads as complete | Consequence: a class sweep states its denominator. Count the source instances first, then account for every one with an outcome: carried, owed, or met by something named. Three recorded and one unmentioned is indistinguishable from three existing | Owner: `DECISIONS.md` D-62; D-39
- `L-029` | Trigger: an exemption or allow-list entry in a check | Finding: an exemption that only excuses a divergence lets a settled decision be reverted silently. Restoring the source value for the one field a decision deliberately changed passed, and the check count dropped from 19 to 18 while the script still reported that every check ran | Consequence: an exemption for a deliberate divergence must REQUIRE the divergence, and a check count that varies with the tree hides a check that stopped being constructed. State the expected count, or name each check in the output | Owner: `DECISIONS.md` D-65
- `L-030` | Trigger: choosing which fields a structural check reads | Finding: reading two named keys left ten of fourteen real references unexamined -- every cross-owner pointer inside an authority block. The keys a check knows about are the ones that existed when it was written | Consequence: scan every string value for the shape you care about rather than enumerating keys, and give out-of-scope content a structural marker the check can recognise. A `repo@sha` lineage string is self-describing; a key name is a guess about the future | Owner: `scripts/Assert-ReferenceIntegrity.py`
- `L-031` | Trigger: a resolution that supersedes a definition | Finding: closing the conflict in the backoffice records left the superseded phrase alive in three places in the governed tree, where agents actually read it. The wording had been chosen to satisfy the narrower definition, so it carried the old reading forward invisibly | Consequence: when a definition is superseded, sweep for the phrasing it produced, not only for the record that stated it. A resolved conflict is not resolved while the governed artifacts still speak in the superseded terms | Owner: `DECISIONS.md` D-66
- `L-032` | Trigger: a directive-given structure that renames or relocates something already accepted | Finding: a corrected sample both relocated global context into the Hub and renamed `runtime-adapters/` to `adapters/`. The first resolved a tension I was about to raise; the second contradicted two accepted records and two earlier decisions | Consequence: apply the later statement from the owner of the taxonomy, and record the supersession explicitly with the records it displaces named. Where nothing is built yet, a rename costs nothing but an unrecorded one leaves two accepted names in circulation | Owner: `DECISIONS.md` D-67, D-68
- `L-033` | Trigger: an owner sends a sample, diagram or example tree | Finding: I twice treated an illustrative sample as authority to restructure live content -- relocating an accepted artifact into a four-level path one message after the owner had confirmed its placement, and renaming an accepted directory. The second happened to be right, which is why the first was not caught by the reasoning that produced it | Consequence: a sample settles the classification model, not the placement of existing files. Record the model, apply it to new content, and leave accepted artifacts where their owner put them until asked. If the model seems to imply a move, say so and ask -- the move is a separate decision, and it is the owner's | Owner: `DECISIONS.md` D-69
- `L-034` | Trigger: adding a level to a hierarchy inside a repository | Finding: `context/global/` was redundant because the Hub is itself the global layer -- the level restated what the repository already meant. The sample that suggested it was drawn as a standalone tree, where the wrapper carried information it loses inside the Hub | Consequence: before adding a level, ask what it distinguishes from its siblings. A level with no sibling distinguishes nothing and costs every path that passes through it | Owner: `DECISIONS.md` D-69
- `L-035` | Trigger: recording a preference the user states in passing | Finding: "I always pull the changes" was written into the record as an unconditional standing routine; the user then scoped it to the present situation with no work in flight. The same session had already converted an illustrative sample into a directory spec | Consequence: record a preference with the scope it was given, present tense included. Generalising it is a second decision, and it is the user's to make. Also check the mechanism before writing the method: terminal commands were handed back for months of pulls done in a desktop client | Owner: `DECISIONS.md` D-71
- `L-036` | Trigger: coining a term, or reusing one the user has never used | Finding: "materialization" spread across a plan, a state file, several decisions and many replies before anyone checked whether it was readable. It meant only "the local folder has caught up with the repository". "While nothing is in flight" was invented the same way and specified a condition nobody needed | Consequence: use the words the user uses. If a concept needs a name, define it once in plain language at first use and keep the plain phrasing available; prefer the plain phrasing outright when it costs no more words. Precision the reader cannot parse is not precision | Owner: `DECISIONS.md` D-72
